# Светлая тема и управление темой

## Задача ветки

Добавить полноценную светлую тему и выбор режима оформления в настройках приложения Windows: светлая, тёмная или автоматическая тема. В автоматическом режиме приложение применяет текущую тему приложений Windows и реагирует на её изменение без перезапуска.

Централизовать управление темой через единый контракт. Подключение других платформ должно требовать только адаптации источника системной темы и платформенного оформления, без дублирования правил выбора темы, хранения настройки и обновления интерфейса.

## Границы

- В этой ветке полностью реализуется и проверяется Windows.
- Общая логика и палитры пригодны для других платформ; реализация и приёмка их автоматического переключения в задачу не входят. Существующее поведение остальных платформ не должно ломаться.
- Сохраняются структура экранов, поведение VPN и поддержка self-hosted, Premium/Free и native-конфигураций.
- Не добавляются другие режимы оформления, новые экраны или несвязанные изменения. Переводы `.ts` не обновляются в рамках этой задачи.

## Исходное состояние

Проверено по исходникам ветки `feature/theme-controller`; наличие кода не означает успешную приёмку функциональности.

- `client/ui/controllers/themeController.{h,cpp}` предоставляет наблюдаемые `applicationColorScheme` и `systemColorScheme`, но пока не содержит выбора режима и его сохранения.
- `client/platforms/systemThemeListener.{h,cpp}` получает тему приложений через Qt и отдельно предоставляет системную тему.
- `client/platforms/windows/windowsThemeListener.{h,cpp}` слушает события Windows и читает `SystemUsesLightTheme`. Это источник оформления системных поверхностей, а не настройка темы приложений Windows.
- `client/core/controllers/coreSignalHandlers.cpp` передаёт системную тему обработчику трея.
- `client/ui/qml/Modules/Style/AmneziaStyle.qml` содержит фиксированную тёмную палитру семантических токенов.
- `client/tests/testThemeController.cpp` содержит проверки уведомлений о смене темы и поведения трея; для нового контракта потребуется расширить покрытие.

## Единый контракт управления темой

Имена ниже описывают целевой контракт. Существующие сущности следует расширить, избегая второго независимого контроллера и параллельных источников состояния.

| Состояние / операция | Семантика |
| --- | --- |
| `themeMode` | Выбор пользователя: `Light`, `Dark`, `System`. Единственная сохраняемая настройка темы. |
| `setThemeMode(mode)` | Единственная операция изменения выбора. Проверяет значение, сохраняет его и пересчитывает эффективную тему. |
| `systemApplicationColorScheme` | Наблюдаемая тема приложений ОС: `Light`, `Dark` или `Unknown`. Не зависит от ручного выбора пользователя. |
| `effectiveColorScheme` | Фактическая тема интерфейса приложения: только `Light` или `Dark`. Вычисляется централизованно. |
| `systemColorScheme` | Тема системных поверхностей Windows, в том числе панели задач. Сохраняется отдельно для трея и не подменяется темой интерфейса приложения. |
| Уведомления об изменениях | Наблюдаемые свойства уведомляют потребителей только при изменении соответствующего значения. |

Правила разрешения темы:

| Режим | Тема приложений ОС | Эффективная тема |
| --- | --- | --- |
| `Light` | Любая | `Light` |
| `Dark` | Любая | `Dark` |
| `System` | `Light` | `Light` |
| `System` | `Dark` | `Dark` |
| `System` | `Unknown` | `Dark` |

- При отсутствии сохранённой настройки используется `Dark`, чтобы сохранить существующее оформление. Некорректное сохранённое значение также разрешается в `Dark`.
- Выбранный режим сохраняется между запусками. Режим и начальная эффективная тема определяются до показа основного интерфейса.
- Вход в `System` сразу применяет актуальную тему приложений ОС. Изменения ОС продолжают отслеживаться и в ручном режиме, но не меняют эффективную тему до выбора `System`.
- Повторная установка текущего режима и повторное событие ОС не вызывают лишних уведомлений. Смена режима уведомляет о режиме даже тогда, когда эффективная тема осталась прежней.
- QML получает выбор и эффективную тему через единый адаптер. Страницы и контролы не читают реестр, настройки или платформенные события и не вычисляют режим самостоятельно.
- Общая логика выбора, проверки и сохранения режима не размещается в QML или платформенном слушателе. UI-адаптер остаётся тонким согласно `AGENTS.md`.
- Платформенный источник только сообщает начальное значение и изменения темы ОС. Он не выбирает палитру и не сохраняет пользовательский режим. Недоступность источника обрабатывается через `Unknown`.
- Обратная связь от применения темы Qt не должна подменять наблюдаемую тему ОС или создавать цикл переключений.

## Поведение Windows и интерфейса

- В настройках приложения доступен один выбор из трёх вариантов: светлая, тёмная, автоматически по системе. Текущее значение видно пользователю.
- Выбор применяется сразу ко всему открытому интерфейсу, включая уже открытые диалоги и всплывающие элементы, без потери состояния экранов и соединения.
- Автоматический режим следует настройке темы **приложений** Windows. При раздельном выборе темы Windows и темы приложений нельзя использовать `SystemUsesLightTheme` вместо темы приложений.
- Трей учитывает тему панели задач независимо от ручной темы приложения, сохраняя индикацию состояния VPN и доступность действий меню.
- Светлая и тёмная палитры предоставляют один набор семантических токенов `AmneziaStyle.color`. Все потребители обновляются через привязки к эффективной теме.
- По последующему указанию пользователя светлая палитра разрабатывается на основе существующей тёмной темы, без исходных данных Figma. Сохраняются визуальная иерархия, нейтральные оттенки и оранжевый акцент. Это согласованное исключение из требования использовать Figma для этой задачи.
- В светлой теме различимы текст, иконки, поля, границы, выделение, фокус, ссылки, статусы и состояния disabled/hover/pressed, включая окна, меню, sheets, уведомления и системные поверхности приложения на светлом фоне Windows.
- Используются существующие компоненты дизайн-системы; новые пользовательские строки проходят через `qsTr()` / `tr()`. Соблюдаются остальные правила `AGENTS.md`.

## Результаты проверок

### Итог реализации Windows

Реализованы три сохраняемых режима (`Dark`, `Light`, `System`), единый контроллер в `core`, реактивная светлая палитра, выбор темы в существующих настройках и независимые Windows-источники темы приложений и панели задач. Qt получает эффективную тему до загрузки основного интерфейса. Восстановление резервной копии и сброс настроек обновляют тему без перезапуска.

- Чистая конфигурация выполнена в `out/build/theme-windows-clean` через Ninja, MSVC 14.51, Qt 6.10.1 и Conan с кэшированными зависимостями. Неисправный кэш Visual Studio не используется.
- Итоговый CMake дополнительно сконфигурирован с кодом 0 в новом пустом `out/build/theme-final-config`, после всех изменений тестовых целей и копирования DLL.
- Полная сборка GUI, сервиса и тестовых целей завершилась с кодом 0. Исправлен общий шаг копирования DLL в тестах для случая пустого списка сторонних DLL.
- Полный CTest: **33/33 набора успешно**. В том числе ThemeControllerTest: **40 passed, 0 failed, 0 skipped**, ThemePaletteTest: **70 passed, 0 failed, 0 skipped** (включая init/cleanup).
- Проверены таблица разрешения темы, режимы хранилища, ошибочные значения, сброс, успешное/ошибочное восстановление backup, уведомления, независимость тем Windows и состояния VPN в трее.
- В QML проверены реальный C++ enum/context, обновление палитры, открытие выбора темы, клик мышью по Light, изменение отмеченного пункта и закрытие drawer. Хранилища приложения и страниц в тесте изолированы от рабочего профиля через отдельные тестовые настройки.
- Application, QR Reader, MtProxy и Telemt загружены и отрисованы нативным QML-движком Windows в обеих темах; ошибок QML, импортов и привязок нет. У MtProxy/Telemt нет рабочего сервера в fixture, поэтому действия на этих страницах проверялись в отключённом состоянии.
- Дополнительная галерея реальных DS-контролов проверяет enabled/disabled/pressed/hover/focus, выделение в трёх текстовых контролах, ошибку поля и статусные цвета. Снимки выполняются после окончания анимаций цвета. Изображения страниц и drawer находятся в `out/theme-resources/pages`; это локальные результаты тестов, они не включаются в коммит.
- Отдельный probe с production-слушателями проверил реальные значения `AppsUseLightTheme` / `SystemUsesLightTheme` во всех четырёх сочетаниях. `SendMessageTimeoutW(WM_SETTINGCHANGE)` доставлялся только собственному скрытому окну, проходя настоящий Win32/Qt native event filter. Повторные события не дублировались; противоположная тема Qt не влияла на источник ОС. Исходные байты, типы и наличие обоих значений реестра точно восстановлены и проверены; probe завершился с кодом 0.
- C++ отформатирован по `.clang-format` в изменённых местах. Переводы и vendored-код не изменялись. Готов переносимый GUI: `out/run/theme-windows/AmneziaVPN.exe`, без установки в систему.

Логи: `out/theme-resources/ctest-windows.txt`, `controller-tests.txt`, `native-probe/native-probe-result.txt`. Для повторной сборки и тестов подготовлены локальные `out/configure-theme-windows.cmd`, `out/build-theme-windows.cmd`, `out/test-theme-windows.cmd`; они не включаются в коммит.

Оставшиеся ограничения приёмки:

- Полная ручная матрица не отмечена выполненной: запуск Settings через computer-use завершился тайм-аутом разрешения доступа. Вместо этого проверены реальные native-события и автоматизированное взаимодействие с QML; ручной сценарий через интерфейс настроек ОС остаётся для проверки.
- Смена темы при живом VPN-соединении, реальные конфигурации self-hosted/Premium/Free/native и все существующие экраны приложения вручную не проверялись. Конфигурации и путь соединения не изменены; автоматические проверки трея покрывают все состояния соединения.
- Другие платформы проверены по условиям сборки и разделению ответственности в исходниках; их сборки и runtime не запускались. Для подключения их автоопределения используются общий контракт/палитры и соответствующий платформенный источник.
- В тестовом окружении остаётся существующее предупреждение `QSystemTrayIcon::setVisible: No Icon set`. При конфигурации есть предупреждение обнаружения MSVC redistributable через незарегистрированный Visual Studio; переносимый runtime собран с локальными CRT, установщик в этой задаче не собирался.

### Светлые ресурсы

Палитра построена по указанию пользователя на основе существующей тёмной темы; исходные данные Figma для этой задачи не требуются. Все 56 прежних значений тёмной палитры сохранены. Два независимых аудита проверили потребителей цветов и изображений. Геометрия существующих SVG, логотип, флаги, QR и иллюстрации сохранены; новые SVG не потребовались.

| Группа | Решение светлой темы |
| --- | --- |
| Поверхности | Светлый базовый фон, белые карточки, нейтральные серые поля и панели. |
| Текст и иконки | Тёмные нейтральные оттенки с сохранением иерархии; светлый текст на инверсных поверхностях. |
| Акцент | Оранжевые оттенки исходной темы затемнены для читаемости на светлом фоне. |
| Статусы | Зелёный, золотистый и красный сохранены по смыслу и затемнены для контраста. |
| Выделение | Светлый `textSelection` на глубоком оранжевом фоне в трёх текстовых контролах. |
| Постоянные цвета | Белый фон QR, постоянный белый текст и прозрачность не инвертируются. |

ThemePaletteTest проверяет заданные пары: текст/основные поверхности, кнопки, выделение и ссылки — не ниже 4.5:1; выбранные значимые индикаторы — не ниже 3:1. Это проверка заданных пар, а не сертификат доступности всего интерфейса. Начальные образцы палитры находятся в `out/theme-resources/preview`; актуальные захваты реальных контролов и страниц — в `out/theme-resources/pages`.

Ресурсный набор также можно запустить отдельно из корня проекта:

```sh
<Qt>/bin/qmltestrunner -input client/tests/qml -import client/ui/qml/Modules -platform offscreen
```
